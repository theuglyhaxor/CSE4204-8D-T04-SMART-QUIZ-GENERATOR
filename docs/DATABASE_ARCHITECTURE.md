# Database architecture

This document summarizes the database schema used by the Django backend.

## Overview

The backend uses **MySQL/MariaDB** through Django ORM and stores:

- Django auth data for users, groups, permissions, and tokens
- quiz data for quizzes, questions, and attempts
- role assignments for teacher and student access

## Core tables

### `quiz_api_quiz`

Stores quiz metadata.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | integer PK | Auto-increment |
| `title` | varchar(255) | Quiz title |
| `description` | text | Quiz description |
| `difficulty` | varchar(50) | Difficulty label |
| `duration_minutes` | integer | Duration in minutes |
| `is_active` | boolean | Active flag |
| `created_at` | datetime | Created timestamp |
| `updated_at` | datetime | Updated timestamp |

### `quiz_api_question`

Stores the questions for each quiz.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | integer PK | Auto-increment |
| `quiz_id` | integer FK | References `quiz_api_quiz.id` |
| `prompt` | text | Question text |
| `option_a` | varchar(255) | Option A |
| `option_b` | varchar(255) | Option B |
| `option_c` | varchar(255) | Option C |
| `option_d` | varchar(255) | Option D |
| `correct_option` | varchar(1) | One of `A`, `B`, `C`, `D` |
| `explanation` | text | Explanation for the correct answer |
| `order` | integer | Display order within the quiz |

### `quiz_api_quizattempt`

Stores student submissions and scores.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | integer PK | Auto-increment |
| `quiz_id` | integer FK | References `quiz_api_quiz.id` |
| `student_name` | varchar(255) | Student name entered at submit time |
| `responses` | json | Stored answer payload |
| `score` | integer | Correct answers |
| `total` | integer | Total questions |
| `created_at` | datetime | Created timestamp |

## Auth and RBAC tables

The app uses Django’s built-in auth tables plus DRF tokens.

### Django auth tables

- `auth_user`
- `auth_group`
- `auth_permission`
- `auth_user_groups`
- `auth_user_user_permissions`

### Token table

- `authtoken_token`

## Relationships

- `quiz_api_quiz` -> `quiz_api_question` : one-to-many
- `quiz_api_quiz` -> `quiz_api_quizattempt` : one-to-many
- `auth_user` -> `auth_group` : many-to-many
- `auth_user` -> `authtoken_token` : one-to-many

## Role usage

The backend assigns users to the `teacher` or `student` group during registration.

- `teacher` users can create and manage quizzes, questions, and attempts
- `student` users can read student-safe questions and submit answers

## Notes

- The schema is generated by Django migrations under `backend/quiz_api/migrations/`
- The sample data script at `sample_data.sql` is a seed script for local development
- The document parsing endpoint does not persist uploaded content to the database; it returns parsed text in the response
